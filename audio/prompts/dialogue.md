# 対話台本の生成（prompt_version: 2026-08-02.1）

`sections/*.md` の本文を読み、**音声で聴いて復習できる対話**を作る。出力は
`academic-audio render --script` がそのまま読む `dialogue.json` 1ファイル。

`scripts/academic_audio/planner.py` の決定論版は、見出しと箇条書きを抜き出して
「確認したいです。」を前置するだけで、対話になっていない。ここで置き換える。

学習者はその資料を一度読んでいる前提。したがって狙いは初出の説明ではなく、
**耳だけで筋を追い直せること**。

## 出力の形

```json
{
  "title": "真理値表",
  "source_id": "logic.ch01.s01",
  "source_commit": "<manifest の commit>",
  "segments": [
    {
      "id": "seg-001",
      "speaker": "host",
      "text": "今日は真理値表を扱います。",
      "language": "ja",
      "emotion": "Neutral",
      "speed": 1.0,
      "pause": 0.4,
      "source_section": "logic.ch01.s01"
    }
  ]
}
```

`id` は `seg-001` から連番。フィールドを増やしたり減らしたりしない。

## これは「読まれる文」ではなく「聴かれる音」

台本を書く前に、その一文が**耳だけで分かるか**を必ず確認する。ここが対話台本の質を
決める。以下は資料をそのまま持ってくると壊れる典型。

| 資料の書き方 | 音にならない理由 | 台本での書き方 |
|---|---|---|
| `- 命題は真または偽の値を取る。` | 箇条書きの構造は音では消える | 「命題というのは、真か偽か、どちらかに必ず決まる文のことです」 |
| `## 基本` | 見出しは音では見出しに聞こえない | 見出しは読み上げず、話題の切り替えとして話す |
| `¬P` | 記号は読み上げられない | 「ピー の否定」 |
| `O(log n)` | 同上 | 「オーダー ログ エヌ」 |
| 真理値表そのもの | 表は音で伝わらない | 「ピーが真でキューが偽のときだけ、全体が偽になります」と言語化する |

`PronunciationNormalizer` が面倒を見るのは `AI` `CPU` `GPU` `CLI` `TTS` の置換、
`` ` `` と `$` の除去、箇条書き記号と見出し記号の除去だけ。**それ以外の略語・記号は
台本の側で開いておく**。「ノット」「ラムダ」のように、読み方が一意でないものは特に。

## 対話の型

`host` が説明し、`learner` が引っかかる。合成音声は `host` が女性、`learner` が男性に
割り当たる（`jvnv-F1-jp` / `jvnv-M1-jp`）ので、**交互に来ると聴き分けられる**。

- `learner` は**具体的に**引っかかる。「確認したいです」「なるほど」のような中身の無い
  相づちで尺を埋めない。「それだと、両方偽のときはどうなるんですか」のように聞く。
- `learner` の疑問は、**その資料を読んだ人が実際につまずく所**に置く。定義の境界、
  記号の読み替え、「なぜそう決めるのか」。
- `host` は 1 回の発話で 1 つのことだけ言う。列挙したくなったら発話を分ける。
- 資料に無い主張を足さない。補足したいときは「ここは資料の範囲外ですが」と明示する。

## 各フィールド

| フィールド | 書き方 |
|---|---|
| `speaker` | `host` / `learner`。`narrator` は対話では使わない |
| `text` | 1発話 = 1呼吸。**60〜120字**。これを超えると合成音声の抑揚が崩れる |
| `language` | 対話は `ja` 固定。英語を混ぜない（後述） |
| `emotion` | 既定は `Neutral`。腑に落ちた所で `Happy`、意外な結果に `Surprise`、つまずきに `Sad` |
| `speed` | 既定は `1.0`。専門用語の初出だけ `0.9` に落とす |
| `pause` | 発話後の無音秒。相づち `0.2` / 通常 `0.35` / 話題の切り替え前 `0.7` |
| `source_section` | 依頼の `review_id`。全セグメント同じ値でよい |

`emotion` は JVNV のスタイルに対応する。使えるのは
`Neutral` `Angry` `Disgust` `Fear` `Happy` `Sad` `Surprise` の 7 つだが、
**講義の対話で `Angry` `Disgust` `Fear` を使わない**。学習の邪魔になる。

## 全体の構成

セクション1つで **8〜14 セグメント / 1分半〜3分**。1発話が 60〜120字なら
合成後は 1 発話あたり 6〜12 秒になる（`pause` 込み）ので、そこから逆算する。

1. `host` が扱う対象を一文で予告する。資料のタイトルをそのまま読み上げない
2. 資料の中心概念を、定義 → なぜそう決めるか → 具体例 の順で解く
3. `learner` の疑問を 3〜5 回挟む。うち 1 つは**誤解しやすい所をあえて間違える**
4. 最後に `host` が想起の問いを投げる。答えは言わない

4 を答えずに終えるのは意図的で、聴き終えた直後に自分で言語化させるため。

## 制約

- 資料に無い数値・定理名・人名を出さない。曖昧なら「資料では触れていませんが」と言う。
- `text` に URL・ファイルパス・`review_id` を書かない。音にならない。
- 同じ語尾を 3 連続させない（「〜ます」「〜ます」「〜ます」）。単調に聴こえる。
- 冒頭の挨拶と自己紹介を入れない。復習音声なので毎回聴くことになる。
- **英語を混ぜない。** 日本語音声モデル（JVNV）は日本語しか合成できない。英語の術語を
  出す必要があるときはカタカナで書く（`in-order traversal` → 「インオーダー トラバーサル」）。
