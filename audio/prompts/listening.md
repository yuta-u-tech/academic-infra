# リスニング教材の生成（prompt_version: 2026-08-02.1）

資料（章の本文、または英語教材）を読み、**Piper で量産するリスニング音声の台本**を作る。
出力は `academic-audio render --script` がそのまま読む `dialogue.json` 1ファイル。

`scripts/academic_audio/listening.py` の決定論版は、正規表現で文を切って
シャドーイングなら同じ文を2回、ディクテーションなら末尾に `Write what you heard.` を
足すだけで、英文そのものは資料から取ってきた生の文。ここで置き換える。

Piper は軽くて速いので、**1文ずつ大量に**作る用途に使う。品質より本数。

## 出力の形

対話台本と同じ `dialogue.json`。`speaker` は `narrator` 固定。

```json
{
  "title": "Logic Circuits Chapter 1 listening",
  "source_id": "logic.ch01.s01",
  "source_commit": "<manifest の commit>",
  "segments": [
    {
      "id": "seg-001",
      "speaker": "narrator",
      "text": "A proposition is a statement that is either true or false.",
      "language": "en",
      "emotion": "Neutral",
      "speed": 1.0,
      "pause": 0.8,
      "source_section": "logic.ch01.s01"
    }
  ]
}
```

## 英語だけで書く（重要）

**Piper に日本語音声モデルは存在しない。** `download_voices` の一覧は en / zh / ko などで、
ja_JP は無い。音声モデルの言語とセグメントの `language` が食い違うとエラーになる。

したがって、issue が挙げている形式のうち **日英対訳・日本語先行は 1ジョブでは作れない**。
日本語部分は Style-Bert-VITS2（44100 Hz）、英語部分は Piper（22050 Hz）になり、
サンプルレートが違うので `output.wav` に結合できない。対訳をやるなら英日で別ジョブに
分けて、後段で揃える必要がある（未実装）。

**今は英語のみの台本を書く。** 日本語の指示文を `text` に混ぜない。
「次の文を書き取りなさい」のような指示は音声に入れず、`dialogue.md`（自動で併産される
人間可読の台本）を答え合わせに使う。

## 何を英文にするか

学習者は資料の内容を日本語では理解している。よって狙いは内容理解ではなく、
**その分野を英語で聴けること**。

- 選ぶ: 資料の中心概念を述べた文、定義文、その分野の論文・講義で実際に出る言い回し
- 選ばない: 資料に出てこない話題、一般的すぎる英会話文、内容の無い例文

資料が日本語なら、**標準的な学術英語に書き直す**。訳ではなく、その内容をその分野の
英語話者が書くならこう書く、という文にする。

## `--listening-mode` との対応

CLI の `--listening-mode` は機械的な変形（`shadowing` は同じ文を2回、`dictation` は
末尾に定型を足す）で、生成した台本にさらに掛かる。**このプロンプトの出力は素の文**に
しておき、繰り返しや指示文を自分で埋め込まない。二重に掛かる。

話速も同じ。`--speeds 0.8,1.0,1.2` がジョブ側で複数生成するので、`speed` は `1.0` 固定。

## 教材の種別

依頼で指定された種別だけを作る。混ぜない。

| 種別 | 何を書くか | 1文の長さ |
|---|---|---|
| `sentence` | 資料の中心概念を述べた平叙文 | 8〜20語 |
| `vocab_example` | 専門語1つを含む例文。その語が実際に取る組み合わせで使う | 8〜15語 |
| `grammar` | 学術英語に頻出の構文（受動態、名詞化、関係詞、分詞構文）を1つずつ含む文 | 10〜20語 |
| `key_sentence` | その章を1文で言うならこれ、という文 | 15〜30語 |
| `toeic_part2` | 質問文1つ。応答は音声に入れず `dialogue.md` 側に置く | 8〜15語 |

`toeic_part5`（穴埋め）は音声にしない。読んで解く形式なので `acenglish` 側の担当。

## 会話形式について

**Piper は 1ジョブ 1音声モデル**なので、複数話者の会話を作っても全員同じ声になる。
TOEIC Part 3・Part 4 のような会話形式は、話者ごとにジョブを分けて別々の
`--piper-model` を当てる必要がある（未実装）。今は単一話者の形式に限る。

## 各フィールド

| フィールド | 書き方 |
|---|---|
| `speaker` | `narrator` 固定 |
| `text` | 英語のみ。1文1セグメント。複数文を詰め込まない |
| `language` | `en` 固定。ここが `ja` だと Piper が拒否する |
| `emotion` | `Neutral` 固定。Piper は感情を持たない |
| `speed` | `1.0` 固定。話速はジョブ側で振る |
| `pause` | `0.8`。書き取る間を取るため対話台本より長い |
| `source_section` | 依頼の `review_id` |

## 件数

1回の生成は依頼の `count` 件まで。**足りない分を水増ししない。** 資料から良い文が
5本しか取れないなら5本でよい。同じ内容を言い換えただけの文を並べると、
シャドーイングで同じ音を繰り返すだけになる。

## 制約

- 資料に無い主張を英文にしない。
- 数式・記号を英文に混ぜない（`O(log n)` ではなく `order log n`）。Piper は記号を
  読み飛ばすことがある。
- 固有名詞・略語は初出で開く（`FPGA` → `field programmable gate array`）。
- 1文に接続詞を2つ以上入れない。耳で追えない。
- 疑問文と平叙文を交互に並べない。ディクテーションで抑揚の手掛かりになってしまう。
