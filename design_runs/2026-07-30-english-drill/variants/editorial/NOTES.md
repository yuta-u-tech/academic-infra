# variant: editorial（エディトリアル / 静謐）

`index.html` 単体で完結。外部依存ゼロ、API 契約は現行 `web/index.html` と同一。

## 狙い

紙の語学書の**見開き**を判型として持ち込む。左段＝文脈（柱・傍注・passage）、
右段＝問いと解答。語彙・読解・文法の3種すべてを同じ1つのグリッドに載せ、
問題が変わっても視線の始点が動かないようにした。
魅力は装飾ではなく、段組・段間・字の大きさの差だけで作る。

## 変えた設計パラメータ

| parameter_path | 現行 | editorial | 理由 |
|---|---|---|---|
| `layout.composition_pattern` | centered（760px 単段） | centered **spread**（440 + 72 + 480 = 992px 2段） | 読解の passage が下へ流れて選択肢を押し出す構造をやめた |
| `typography.scale_ratio` | 1.25（32 / 20 / 12） | **1.7 前後**（38 / 22 / 13） | 段間 1.73・1.69。1.2倍差を作らないため文字サイズを4つ（57 / 38 / 22 / 13）に畳んだ |
| `typography.families.display` | sans（Hiragino Sans） | **serif / 明朝**（ui-serif → Hiragino Mincho ProN） | 語学書の版面。和文の語義が主役になる |
| `typography.families.body` | mono（英文・選択肢すべて） | **serif**（英文・選択肢・解説）／mono は数値・柱・伏せ字・キー表記だけ | 英文を等幅で組むと「端末の出力」に見える。選択肢の語形比較は同サイズ左揃えで足りる |
| `color.neutrals` | 夜（#0B0D10 系） | **紙**（#F7F4EE / #EFEBE2 / #D6CFC3 / #17150F / #6A635A） | 暖色ニュートラル1系統。低彩度 |
| `color.accent` | #4C8DFF（彩度高） | **#2B4661**（低彩度の藍、on paper 8.9:1） | 使用箇所は空所の罫・選択中の左罫・正解語・進捗の2px のみ |
| 正誤色 | `--ok` #3FB950 / `--ng` #F85149 | **持たない** | 色相2つを厳守。正誤は語（正解 / 誤り 38px）・濃度・左罫・「こたえ / じぶん」の小見出しで示す |
| `layout` 選択肢の形 | 角丸ボックス4つ | **罫だけの列**（箱を外す） | 箱が4つ並ぶと視覚的重量が問いと拮抗する |
| 答え合わせ | 下部固定パネル（max-height 56vh、本文を隠す） | **右段 sticky**（left が伸びても判定・解説・手応えが視野に残る） | 問いと解説が同時に見える |

## 現行案より良くなった点

- **読解が1画面で完結する。** passage・設問・選択肢4つ・キー表記が 1440×900 の
  fold 内に全部入る（実測: 版面下端 789px < キーバー上端 840px）。
  現行は passage だけで fold を使い切り、選択肢4番目が切れていた。
- **答え合わせで問いが隠れない。** 現行の下部パネルは画面の 56% を覆い、
  選択肢の3・4番が見えなくなる。右段 sticky なら左段の全選択肢が残る。
- **出題中も答え合わせ中も色相は2つだけ。** 緑/赤を一切持たないので、
  「色が答えの手がかりになる」問題が構造的に起こり得ない。
- **柱（`01 / 20`）のベースラインが右段の1行目のベースラインと一致する**
  （高さ0の inline-block を挿して実測し、`.margin` の padding-top を 17px に決定。
  答え合わせは 9px、扉は 37px）。段がずれて見えない。

## 自分で見て直したもの

1. `--colw-*` を `ch` で持っていたため、`ch` が root の 17px で解決されて
   22px の passage が実測 30字詰めまで痩せていた → px 指定に変更
2. `main` が border-box なのに max-width に padding を足しておらず、版面が 48px 痩せて
   キーバーの左端と柱の左端が 24px ずれていた → calc に padding を加算
3. `.stem .blank` という選択子だったため、答え合わせの控え（`.recap-stem`）で
   空所の罫が消えていた → `.blank` 単独に
4. 和文の語義が `（会議・式などを）` のように全角括弧で始まると1行目だけ右にずれる
   → `.lead-paren`（`text-indent: -.5em`）を JS 側の判定で付与
5. passage の drop cap（`::first-letter`）が2行目に食い込んで整列が折れて見えた → 削除
6. 伏せ字 `#B3AB9E` は紙に対し 2.07:1 で文字数が数えられない → `#8A8175`（3.49:1）
7. 答え合わせの未選択肢 `#A29A8E` が 2.53:1（大文字 3:1 未満）→ 同上
8. 19px / 18px が 22px と 1.2倍差しかなく「揃え損ね」に見えた → 22px に統合
9. 1段に畳んだとき `.panel { order: -1 }` が効いていなかった（panel は grid item の孫）
   → `.spread.verdict > section { order: -1 }`。狭幅でも手応えがスクロールなしで押せる

## 捨てたもの

- **等幅での英文組み**。選択肢の `-ly / -ing` の字幅を揃える利点は捨てた。
  同サイズ・左揃え・罫で区切った列なら語尾の比較はできる。
- **正誤の色**。一目で分かる速さは 38px の「正解 / 誤り」に置き換えた。
- **選択肢の箱**。ホバー/選択は左罫 2px と地色（`--paper2`）と 16px のインデントで示す。
- **答え合わせの下部固定パネル**。狭幅では順序入れ替えに、広幅では sticky に置換。
- **問題文の等幅・引用左罫**。段そのものを引用の枠にした。

## 残っている弱点

- **語彙の画面が空きすぎる。** 版面占有は縦 267px（読解は 693px）で、
  柱と入力欄しかない左右の余白が大きい。書物の余白として読める範囲だとは思うが、
  「間で語る」の限界に近い。種別ごとに天の空きを変えると柱が跳ねるので採らなかった。
- **傍注に API の生の語が出る**（読解の `comprehension`、文法の `point` は日本語だが
  読解は sub_skill をそのまま出している）。日本語対応表を持つべきだが、
  API 契約を変えない範囲では JS 側の辞書追加になるので今回は据え置いた。
- **`.panel` の内部スクロール**。解説が非常に長い場合、右段が
  `max-height: calc(100vh - ...)` で内部スクロールになる。手応えボタンには
  キーボード `1`–`4` で常に到達できるが、マウス操作だと1回スクロールが要る。
- **明朝の可用性**。macOS 以外では `ui-serif` → Georgia 系にフォールバックし、
  和文が游明朝/ヒラギノ明朝でなくゴシックになる環境があり得る（127.0.0.1 の
  ローカル利用が前提なので許容した）。
- **狭幅（1000px 以下）の答え合わせで柱が孤立する。** 判定パネルを先頭に出す
  順序入れ替えの副作用で、`02 / 3` の柱が画面最下部に取り残される。
  実害はない（rank3）が、形としては据わりが悪い。
- **語彙の入力行で、打った文字と最初の伏せ字の間が空いて見える。**
  伏せ字に `letter-spacing: .38em` を掛けているため先頭の1字に余分な字送りが乗る。
  文字数の数えやすさとのトレードオフとして今回は据え置いた。
- **`.spread` の柱合わせが手当ての量で成立している。** `.margin` の padding-top
  17px / 9px / 37px は書体メトリクスからの実測値で、書体が差し替わると崩れる。
  本来は grid の baseline alignment で解くべきところ。
