# variant: luminous — 発光する深度 / マテリアル

## 狙い

現行案は「暗い背景に文字と枠線が浮いているだけ」で、面がない。
面（surface）を1枚だけ立てて、その上端に光を当てて持ち上げる。
出題は持ち上がった面、本文と入力欄は沈んだ面、答え合わせは下から立ち上がる面。
光源は画面上端中央のひとつだけで、すべての光沢はその向きに従う。

## 変えた設計パラメータ

| parameter_path | 現行 | luminous | 理由 |
|---|---|---|---|
| `color.neutrals[0]` (bg) | `#0B0D10` | `#07080B` | 面を1段上げるために底を下げる |
| `color.neutrals[1]` (surface) | `#14181D` 単色 | `#151A22 → #0D1117` の縦グラデ | 上が明るい＝光源が上、を面そのもので示す |
| — (新規) 沈んだ面 | なし | `#0A0D12` + inset shadow | passage と入力欄を「へこみ」として区別 |
| `color.neutrals[2]` (border) | `#232A32` 実線 | `rgba(255,255,255,.07)` + 上端 lip `.065` | 線ではなく稜線。角度で明るさが変わる |
| `layout.composition_pattern` | centered（要素直置き） | centered + 単一カード | 主役の外周を1本にまとめる |
| `--radius` | 6px 一律 | 16 / 12 / 10 / 6 の入れ子 | 外→内で落とす。角丸の不統一は作らない |
| `medium.canvas` 実効幅 | 760px | 800px（カード内寸 752px） | padding 32px を足しても行長が現行と同等 |
| 選択状態のチャンネル | border-color のみ | 面の色 + 稜線 + 外側 glow | 「選んだ1枚だけが光る」＝焦点が1つ |
| 進捗 | 1px 実線 | 2px（溝 + 発光する帯） | 残量が読める。1px は溝がなく量が見えなかった |
| 質感 | なし | 4px ドット + 斜めの粒（計 α≦.02） | 画像・外部依存なしで平面に粒を与える |
| `hierarchy.levels` | 4項目 | 変更なし（32 / 20 / 12） | 段間 1.6倍以上を維持 |
| `quality_rules.max_hues` | 2 | 変更なし | 答え合わせの既定ボタンも accent を使わず明度だけで示した |

accent（青）の使用箇所は 進捗の帯 / 空所の下線 / 選択中の1枚 / caret / 開始ボタン のみ。
出題中の画面で accent が占める面積は 1% 未満。正誤色は答え合わせ後だけ。

## 現行案より良くなった点

- **焦点が1つになった。** カード上端の微発光（`radial-gradient` α.10）に視線が入り、
  eyebrow → 問題文 → 選択肢と落ちる。現行は全要素が同じ平面にあり入口がない。
- **選択が「光る」ので状態が読める。** 現行は border-color の変化だけで、
  1440px 幅では選択の有無が離れて見て分からなかった。
- **読解で選択肢4まで届く。** 本文を面の中でスクロールさせ（上限 214px）、
  選択肢4の下端を y=840 に収めた（現行は y=1065 でページスクロールが必須）。
  切れ目は下端のフェードで示し、続きがあることが分かるようにした。
- **手応えボタンが必ず操作できる。** シートを flex 縦積みにし、解説側だけ伸縮＋スクロール、
  手応え側は `flex:none`。解説がどれだけ長くてもボタンは画面内に残る。
- **キー説明の二重表示をやめた。** 答え合わせ中は下端の keybar を消し、
  同じ内容をシートの中に置いた（現行は同じ文言が2箇所に出ていた）。

## 捨てたもの

- **passage を全文表示すること。** 選択肢4に到達することを優先し、7行で切って
  面内スクロールにした。長文を一望したい使い方なら現行案の方が良い。
- **タグの実線枠。** `chip` に置き換えて、面の一部として扱った。
- **カードの縦中央寄せ。** 語彙・文法では下に 300px 前後の余白が残るが、
  問題ごとに設問の縦位置が動くと連続で解けないため、上寄せ固定を維持した
  （`project_style_profiles.md` で意図的に受け入れた balance 0.73 を踏襲）。
- **答え合わせの既定ボタンに accent を使うこと。** 赤（不正解）と同時に立って
  色相が2つ増えるため、明度だけの合図に落とした。

## 残っている弱点（時間切れ。直していない）

1. **本文の上限 214px が 1440x900 決め打ち。**
   選択肢4の下端が keybar の不透明域（y≈853）に入らない上限として実測で決めた値。
   ウィンドウが低いとやはりページスクロールが要る。本来は選択肢の実高から
   逆算して動的に決めるべきで、その実装はしていない。
2. **読解でカードの下端（y≈872）が keybar のフェード帯に潜り、角丸の下端が見切れる。**
   「面をひとつの物体として見せる」という狙いと矛盾する箇所。
3. **語彙・文法でカード下に 300px 前後の余白が残る。**
   上寄せ固定（設問の縦位置を動かさない）を優先した結果。空白自体は意図通りだが、
   カードが画面上部に貼りついて見えるバランスは詰めきれていない。
4. **伏せ字の点のコントラスト 2.69 は AA 未満。**
   読ませないための濃度なので意図的だが、AA を満たす範囲でどこまで落とせるかは未検討。
5. **語彙の入力欄（460px 固定）が中身より広く、右に余白が残る。**
   語ごとに幅が動くと入力位置が動くため固定にしたが、fixture 1件でしか確認していない。
6. **選択肢タイルの明暗が交互に見える現象を切り分けていない。**
   スクショ上で1・3枚目が2・4枚目より明るく見えた。CSS 上は全タイル同一のため
   縮小表示のアーティファクトと判断して放置した。実機未確認。
7. **`.well.is-clipped` の判定が初回描画時の1回だけ。**
   リサイズでスクロールの要否が変わってもフェードが付け外しされない。
8. **答え合わせのシートが選択肢4を覆う。**
   現行案と同じ挙動だが、正解が4番だったときに正解が見えるかを検証していない。
9. **確認したのは 1440x900 と 500x844 の2幅のみ。**
   headless Chrome が 500px 未満に窓を縮められないため、genome の
   responsive_target である 390px は実機で見ていない。
10. **他バリアントとの相対評価はしていない。** 単体で閉じた自己批評のみ。

## 実測

- JS: `node --check` 通過（インライン script 抽出、最終版で再確認）
- コントラスト（実際に重なる面の色で計算）: 本文 14.8 / meta 5.7〜6.5 / accent 5.7 /
  ok 6.9 / ng 5.2 / 開始ボタン 6.3 — 全て AA
  - 例外: 伏せ字の点 2.69。読ませないための濃度で、文字数を数える用途にだけ使う
    （現行の `#46505C` on `#14181D` = 2.2 より改善）
- タップ領域: 選択肢 54〜84px / 手応え 62px / select・開始 44px — 全て 44px 以上
- 1440x900 と 500x844 で撮影して確認（headless Chrome は 500px 未満に窓を縮められない）
- `prefers-reduced-motion: reduce` で animation / transition を全停止

## 前提

- 単一 HTML。CDN・外部フォント・npm なし。`file://` で開いても崩れない
- API の契約は `API_CONTRACT.json` のまま。リクエスト／レスポンスの形は一切変えていない
- 出題中に出すのは `meaning` / `part_of_speech` / `answer_pattern` / `sentence` /
  `passage` / `question` / `choices` だけ。`collocations` は現行では出題中も表示しうる
  実装だったが、答え合わせ後のみに絞った
