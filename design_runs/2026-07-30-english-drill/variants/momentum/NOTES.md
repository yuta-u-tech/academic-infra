# variant: momentum

## 狙い

毎日回すドリルの魅力は「進んでいる感じ」だが、それを星やトロフィーで代弁させない。
画面上端に固定した **rail 1本**（1セグメント = 1問）に進捗・正誤・現在地・ペースを全部畳み込み、
本文領域からは進捗表示を追い出した。1画面の主役は常に「いま解く1問」のまま、
周辺視野だけで「今日の残り」と「連続で当たっている」が分かる状態を作る。

## rail の読み方（実装した符号化）

色相は増やさず、**明度3段** だけで表す。

| 状態 | 見え方 |
|---|---|
| 未着手 | `#1D242B`（ごく暗いトラック） |
| いま解いている | 左端に 2px の accent、想定時間をかけて accent が左→右に伸びる |
| 正解 | `--fg`（明るく塗り潰し） |
| 不正解 | `#3E4751`（中間色） |

正解が続くと明るいセグメントの塊になる。これが連続正解の可視化で、カウンタの演出は要らない。
数値の `連続 N` は 2 以上のときだけヘッダに出す（変化するものだけが動く）。

**すべてセッション内で数え切れる値のみ。** サーバーが返さない累積統計・生涯ストリークは作っていない。
`mastery` はサーバーの返り値をそのまま出し、伸び幅は捏造しない（10目盛の帯を添えて桁の意味を読めるようにしただけ）。

## 現行案から変えた設計パラメータ

| parameter_path | 現行 | momentum | 理由 |
|---|---|---|---|
| `layout` 進捗表現 | 画面最上端 1px の連続バー | 20分割の rail（68→76px の固定 HUD 内） | 「残り」だけでなく「何問目・当たったか・いまどこか」を1本で持たせる |
| `layout.composition_pattern` | centered / 上寄せ | centered + 上下固定フレーム（HUD + keybar） | 空白が「余ってる」ではなく「枠で抑えている」に見える |
| `medium.canvas` 本文幅 | 760px | 720px（内側 24px を除いた 672px が行長） | 行長を詰め、rail / 本文 / keybar の左右端を1本に揃えた |
| stem の縦位置 | 上寄せで種別ごとに変動 | 語彙・文法は `padding-top: hud + 96px` で固定、読解のみ詰める | 毎問 stem の y が動くと視線が主役を探し直す。速く回すほど損をする |
| 選択肢の選択表現 | 行の border-color を accent に | 共有マーカー 1本が 130ms で行間を滑る + 行の背景 | 押した瞬間に「効いた」感触。視線が現在位置を失わない |
| 選択肢の枠線 | 全行に border | 枠線なし（背景 + マーカーのみ） | 4本の枠が stem と競合していた。主役を戻す |
| `spacing` 選択肢 gap | 8px | 4px（枠線を消したぶん詰めた） | 枠がないので余白だけで分離する |
| 状態遷移 | なし | 出題 140ms fade+6px rise / 判定パネル 160ms lift / rail commit 200ms | 速く回せることを気持ちよさに変える |
| ヘッダ情報量 | 6項目（番号・正答率・時計・難易度・種別・point） | 5項目、難易度は verdict へ移動 | 出題中に難易度は行動を変えない |
| 正答表示 | `正答 85%`（1問ごとに大きく跳ねる） | `正答 3`（実数・等幅・幅固定スロット） | 少数問で% は暴れる。桁の揺れも止めた |
| セットアップ | 科目・種別 | + `今日の分`（10/20/40） | 「今日の残り」を正直に表すには session-local な目標が要る |
| 終了画面 | 解答数・正答率 | + 最長連続・ペース中央値 + rail 全体 | セッションの記録をそのまま返す。平均でなく中央値（1問の長考で壊れる） |

## 現行案より良くなった点

- 進捗が**常に見える**（読解で passage をスクロールしても HUD は固定）。現行は 1px バーが視界から消える
- rail / 本文 / keybar / verdict の左右端が全部 384px で揃った（現行は verdict と keybar が本文より 24px 外側にいた）
- 読解の選択肢4つ目が 900px の fold 内に収まった（passage 下マージンと上部余白の圧縮で 24px 捻出）
- 手応えボタンが `position: sticky` で必ず見える（狭い画面で解説がパネルを埋めても操作できる）
- verdict パネルを `body` 直下へ移した。`main` に transform が乗る瞬間に包含ブロックが `main` になってパネルが浮く事故を構造的に消した

## 捨てたもの

- **セグメント幅にペース履歴を持たせる案**。速く答えるほどセグメントが短くなる棒グラフは魅力的だったが、
  5% の塗りは「未着手」と見分けがつかず、済/未が読めなくなった。ペースは live セグメントと終了画面の中央値に逃がした
- **縦中央揃え（`align-content: safe center`）**。語彙の下半分の空白は消えるが、種別ごとに stem の y が 90px 動く。
  毎日回す道具では位置の安定のほうが価値が高い
- **正答率(%)**、**次回間隔の事前表示**（grade を押す前の `interval_days` は暫定値で、手応えボタン自体が同じ問いに答えている）
- 難易度ドットの出題中表示

## 残っている弱点

- 語彙は下半分が 500px 前後空く。1語のプロンプトである以上コンテンツが足りず、フレームで抑える以上の解がない
- 390px 幅では verdict パネル（54vh）が選択肢を完全に覆う。答えはパネル内に再掲されるので情報は落ちないが、
  自分がどれを選んだかは見えない
- rail は 40問を超えると 1セグメント 16px を割る。目標を 40 より大きくする UI は用意していない
- `prefers-reduced-motion` では pace が伸びない（嘘の時間を描かないため）。現在地は左端 2px の accent だけが示す

## 検証

- `node --check`（インライン script 抽出）: pass
- 外部参照 0 件（`src` / `href` なし、CDN・外部フォントなし）。単一 HTML
- 1440×900 / 390×840（iframe による実寸ビューポート）で横溢れなし
- API 契約は現行 `web/index.html` と同一（`/api/courses` `/api/sessions` `/api/queue` `/api/hint` `/api/answer` `/api/grade` `/api/sessions/{id}/end`）。
  `exclude` を使った 20問ごとのキュー補充もそのまま

### スクリーンショットの注意

headless Chrome の `--screenshot` はビューポートより高い/広い面を撮り、`position: fixed` を
撮影面の下端に貼り直す。`--window-size=1440,900` では `innerHeight` が 757 になるため、
**1440×1043 で撮って上から 900px を実ビューポートとして読む**こと。
`05-verdict.png` でパネルが切れて見えるのはこの副作用で、実測は top 550 / bottom 900（切れていない）。
390px の確認は iframe（`width:390px`）で行う。headless の最小ウィンドウ幅は 500px。
