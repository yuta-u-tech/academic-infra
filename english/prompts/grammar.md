# 空所補充の文法問題の生成（prompt_version: 2026-07-30.1）

依頼 JSON の `material` を読み、**TOEIC Part 5 と同じ形**の空所補充問題を作る。出力は
`english/schema/generation-result.schema.json` に準拠した JSON 1ファイル。

市販の問題集から問題文を写さない。素材（VOA の記事・TED の字幕・TOEIC 語彙）に出てくる
語と場面を使って、こちらで作る。

## 難易度の目標（900点、990点ではない）

TOEIC900点は「Part5の正答率8割を超えている」帯にあたる（`900点特急 パート5&6` の対象読者
記述。出題数の正確な内訳は教材により記述が揺れるため断定しない）。この帯では、
**品詞の形さえ知っていれば意味を読まなくても解ける問題
（600点レベル）を主力にしない。** 具体例:

- 600点レベル（避ける）: `The report was submitted ____.` 選択肢が
  `punctual/punctually/punctuality/punctualize` のように**同じ語の語形違いだけ**の問題。
  空所の直前直後（動詞の後）を見れば副詞と分かり、文の意味を読む必要が無い。
- 900点レベル（狙う）: `Remember that work-life balance issues can _______ anyone in any
  stage of the life cycle.` 選択肢に `affect`（動詞・影響する）と `effect`（名詞・効果）の
  ような**似ているが別の語**を混ぜ、語彙の意味と品詞の両方を知らないと解けない形にする。
  `can` の後だから動詞、という統語知識だけでは絞り切れない語彙を選ぶ。
- 990点レベル（狙わない・出しすぎない）: 選択肢が `inversion/intrusion/aversion/invasion`
  のように**語幹まで似た低頻度語**の識別だけを問う問題。ビジネス文脈で滅多に出ない語で
  作らない（TOEICで実際に使われる語彙の範囲に収める）。

**目安: 1回の生成のうち、同じ語の語形違い（`choices`パターンA、下記）だけの問題は半分以下に
抑え、残りは似た別語の混同（パターンB）か、空所前後だけでなく文全体を読まないと絞れない
文脈依存の問題にする。**

### 較正ログ

- 2026-08-05: パターンBの初回セット（`affect/effect`・`raise/rise`・`economic/economical`・
  `despite`+動名詞・`assure/ensure/insure`、パターンA 1問・パターンB 4問）を出題したところ
  **5問全問正解**。方向性は良いが、もっと難しくてよいとのフィードバック。
  → 上記の対応として、パターンCを新設し、パターンBは
  `affect/effect` のような**定番すぎて既に知られている組**を避け、下記「語彙候補」の
  ようなやや低頻度の組を優先する（ただし990点向けの語幹一致型ほど極端にはしない）。

### パターンC（コロケーション知識）— 追加

文法的にも語彙的にも複数の選択肢が成立し得るが、**その文脈で実際に使われる語の組み合わせ
（コロケーション）を知っているかどうかでしか正誤が決まらない**問題。965点ホルダーの解説でも
「語彙問題は知識問題であり、考えても答えは出ない」と言われるタイプで、消去法や文法規則からの
逆算が効きにくいぶん難度が上がる。例: `significantly increase`（○）に対して意味は近いが
コロケーションとしては不自然な副詞を誤答に混ぜる。**パターンB・Cを合わせて全体の7割以上**を
目安にする（パターンAは残りの3割以下）。

### パターンB/Cで使える語彙候補（`affect/effect`ほど手垢が付いていない組）

`complimentary`（無料の・称賛の）vs `complementary`（補完的な） /
`principal`（主要な・校長）vs `principle`（原則） /
`considerable`（かなりの）vs `considerate`（思いやりのある） /
`eligible`（資格がある）vs `legible`（読める） /
`respective`（それぞれの）vs `respectful`（敬意を払う） /
`economic` vs `economical`（既出だが有効）。
**`affect`/`effect` は今回のセッションで既に使用済みのため、しばらく使わない。**

## sentence

- 1文。空所は `____`（アンダースコア4つ）ちょうど1箇所。
- 素材に出てきた語・話題を使う。素材と無関係な一般例文で埋めない。
- ビジネス文脈（会議・注文・出張・人事）を優先する。TOEIC の出題場面がそこに偏るため。

## choices / answer_index

- 4択が基本（3–5択まで可）。`answer_index` は 0 始まり。
- ランダムな無関係語を混ぜない。1つでも混ざると消去法で解けてしまう。
- 誤答選択肢は次の3パターンのいずれかで作る（上の「難易度の目標」の通り、
  パターンB+Cを合わせて7割以上にする）:
  - **パターンA（同じ語の別の形）**: 「意味を知っているか」ではなく「形を選べるか」を問う。
    - 品詞: `succeed` / `success` / `successful` / `successfully`
    - 態・時制: `has completed` / `was completed` / `completing` / `to complete`
    - 前置詞・接続詞: `despite` / `although` / `because of` / `however`
  - **パターンB（似ているが別の語）**: 「形が同じでも意味・品詞が違う語」「スペルや音が
    近い別の語」を混ぜ、意味を読まないと絞れない形にする。上の「パターンB/Cで使える語彙
    候補」から選ぶ（990点向けの極端に低頻度な語幹一致まで踏み込まない）。
    選んだ語がなぜ紛らわしいかを `explanation` で必ず説明する。
  - **パターンC（コロケーション知識）**: 文法的にはどれも成立しうるが、その語と実際に
    結びつく語（動詞+副詞、動詞+前置詞、形容詞+名詞 等）の知識だけで正誤が決まる形にする。
    `explanation` には**なぜその組み合わせが自然/不自然か**を、文法規則ではなく
    「実際にそう使われるから」という形で書く（規則で導けない、というのがこのパターンの
    本質のため）。

## point

問われている文法項目を短く書く（`副詞と形容詞の区別` / `分詞構文` / `前置詞 vs 接続詞`）。
**誤答が同じ `point` に集中したとき、文法ノートのどこを書き足すべきかがこれで決まる**ので、
「文法」のような粗い書き方をしない。

## explanation

正解の理由に加えて、**各誤答がなぜ入らないか**を書く。誤答時にそのまま提示される。

## sub_skill

| 値 | どういう問題か |
|---|---|
| `knowledge` | 規則そのものを知っているかを問う |
| `recognition` | 正しい形を選べるか（Part 5 の標準） |
| `production` | 与えられた語を適切な形に変えて入れる |
| `processing_speed` | 平易だが即答が要る |

## 制約

- 空所は1つだけ。2箇所空けない。
- 正解が2つ成立する文にしない（曖昧なら文脈を足して1つに絞る）。
- 1回の生成は依頼 JSON の `count_per_kind` 件まで。
