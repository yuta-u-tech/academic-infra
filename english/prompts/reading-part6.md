# 長文穴埋め問題（TOEIC Part6 相当）の生成（prompt_version: 2026-08-14.2）

**TOEIC Part 6 と同じ形**の長文穴埋め問題を作る。Part5（`grammar.md`）の「1文=1空所」を
「1passage=4空所」に拡張したもの。市販の問題集からパッセージ・問題文を写さない。

## 較正ログ（2026-08-14、初回セットの検証結果）

初回セット（16問、passage 4件）を独立agentにWeb検索付きで検証させたところ、**ユーザーの
「簡単すぎる・同じ問題が多い」という指摘は妥当だった**。16問中12問がPart5と同じ「その1文
だけで解けるローカル問題」で、Part6の本来の目玉である**時制・接続副詞（However/Therefore等）・
代名詞照応の3タイプが1問も無かった**。さらに「to不定詞に続く動詞の原形」を3passageで
使い回す形式的な繰り返しがあり、TOEICで出ない不自然な語（`accession`/`requited`等）も
混入、文挿入問題も接続詞・指示語などの文脈手がかりが無く消去法で解けてしまっていた。
下記の制約は、この検証結果を踏まえて追加したもの。**この節の制約は既存の他の節より優先する。**

## 出力するJSONの構造

トップレベルは `toeic_reading_cli.py worksheet-part6`/`shuffle-part6`/`ingest-part6` が
そのまま読む形（Part7の`reading-part7.md`と同じpassagesグルーピングだが、questionsの
中身がPart5のGrammarItemに近い）:

```json
{
  "title": "Part6 <YYYY-MM-DD>",
  "passages": [
    {
      "passage": "本文。空所は [1]〜[4] で示す（____ ではない。Part5と記法を変えているのは、
        1passageに4箇所あるため番号で区別する必要があるため）。",
      "passage_type": "email",
      "questions": [
        {
          "blank_number": 1,
          "blank_type": "word",
          "choices": ["...", "...", "...", "..."],
          "answer_index": 0,
          "explanation": "...",
          "point": "...",
          "pattern": "A",
          "pattern_note": "..."
        }
      ]
    }
  ]
}
```

- `passage_type`: `email` / `memo` / `notice` / `advertisement` / `article` のいずれか。
  **4passageで4種類とも異なるものを使う**（似た話題・似た文書の使い回しをしない。
  2026-08-14の初回セットは4件中3件が「施設の閉鎖/移転/改修のお詫び」で酷似していた）。
- `questions`は`blank_number`の1〜4を**必ず全て含む**（4問ちょうど）。
- **1passageにつき`blank_type: "sentence"`（文挿入）が必ず1問**、残り3問が`blank_type: "word"`
  （`pattern`(A/B/C)/`pattern_note`必須）。**文挿入の位置（blank_number）は4passageで
  1・2・3・4のいずれかにばらけさせる**（2026-08-14の初回セットは3/4passageで文挿入が
  blank_number=3または4に固定されており、位置から見抜けてしまっていた）。

## 1セット全体（16問）で満たす構成比（2026-08-14追加、最重要）

作問前に「どのblankでどのタイプを出すか」を16問分あらかじめ割り付けてから書くこと。
実際のPart6（複数の対策サイトの集計の目安）に合わせ、**word型12問の内訳を**:

| タイプ | 目安数(12問中) | 説明 |
|---|---|---|
| 時制・態（動詞の形） | 2〜3 | 前後の文の時制と整合するかを問う。1文だけでは決まらない設計にする |
| 接続副詞・前置詞句 | 2〜3 | However/Therefore/In addition/As a result等、前後の文の論理関係で決まる語を選ばせる |
| 代名詞・指示語 | 1 | it/they/this/these等、何を指すかが前の文でしか分からない設計にする |
| 品詞（word-form） | 上限4 | 初回セットは7/16と過多だった。品詞問題ばかりにしない |
| 語彙・コロケーション | 3〜4 | Part5と同じくパターンB/C |

**「時制・接続副詞・代名詞」の3タイプ合計で最低5問**は1セット16問中に必ず入れる
（初回セットはこの3タイプが合計0問だった）。この3タイプは`pattern_note`に「どの文の
どの情報を根拠に絞るか」を明記すること（例:「前の文が過去形なので、対応する時制の
`had been`が正解」）。**その根拠となる文を名指しできない場合、それは実質Part5の
1文問題であり、Part6として不適格**——書き直すこと。

同じ`point`（文法/語彙項目）や同じ語幹の語（`access`/`accessible`等）を**16問中で2回以上
使わない**（初回セットは「to不定詞に続く動詞の原形」を3回、`access`語幹を2回使っていた）。

## word型の空所（choices/answer_index/point/pattern/pattern_note）

`grammar.md`の「choices / answer_index」「point / pattern / pattern_note」節と同じ基準
（パターンA=同じ語の別の形、B=似ているが別の語、C=コロケーション知識）。Part6は文書全体の
文脈（前後の文・段落）を読まないと絞れない設計にする——Part5と違い1文だけでは解けない
問題を混ぜてよい（むしろそれがPart6らしさ）。

- **誤答の4語は、ビジネス英語で実際に使われる自然な語に限る。**`accession`/`requited`/
  `temporariness`のような低頻度・不自然な派生語を誤答に使わない（TOEICで出ない語は
  読んだ瞬間に消去できてしまい、実質2択問題になる。初回セットの欠陥）。
- **正解を選んだ後、残り3つの誤答それぞれが「その文脈で本当に不成立か」を書きながら
  自己チェックする。**文法的にも意味的にも成立してしまう誤答が無いか確認する
  （初回セットは"move onto the next phase"が正解"into"と同様に成立してしまう欠陥が
  あった。前置詞・接続詞の問題で特に起こりやすいので要注意）。

## sentence型の空所（文挿入、choices/answer_index）

- **正解の文には、必ず接続詞的な語句（However/Therefore/In addition/As a result/Also等）
  か指示語（this/these/that/it等、直前の文の何かを指す）のどちらかを含める。**
  トピックが合っているというだけで解ける文（何の接続語も指示語も無い文）にしない
  （初回セットの欠陥。ユーザー指摘・検証agent確認済み）。
- 誤答4択中**少なくとも2つは「話題は合っているが内容が誤り」**にする（例: 時期が違う・
  対象者が違う・前の文の内容と矛盾する）。残りの1〜2つを「話題自体が違う」文にしてよいが、
  4択全部が明後日の方向の話では消去法で一瞬で解けてしまうため避ける。
- `explanation`には、なぜ正解が流れに合うか（接続語/指示語が何を受けているか）、
  誤答がなぜ話の流れに合わないかを書く。

## passage

- 200〜250語程度のビジネス文書（社内連絡・注文確認・イベント案内・製品案内・お知らせ等）。
- 1passageに1つの話題。段落は2〜4個程度に分ける。

## explanation / point

`grammar.md`と同じ基準（誤答ごとに正しい使われ方を示す。`point`は「副詞と形容詞の区別」
のように具体的に書く）。

## 1日あたりの出題

既定は「4 passage × 4問 = 16問」。Part5と同じく通常＋苦手重点の2段構成を想定するが、
`toeic_reading_cli.py weak-points-part6`の誤答データが少ないうちは全passage通常配分でよい
（無理に苦手重点を捏造しない）。データが溜まってきたら1passageを苦手重点に差し替える。

書いた直後、`worksheet-part6`/`ingest-part6`/Form作成のいずれよりも前に、必ず
`toeic_reading_cli.py shuffle-part6 --items items.json` を実行すること（passage順序・
選択肢順序を機械的にシャッフルする。review_idはシャッフル後の順で決まる）。
