# 英文読解問題の生成（prompt_version: 2026-07-30.1）

依頼 JSON の `material`（= `sections/*.md` の本文）を読み、**その内容を英語で書き直した
短い passage** と、それに対する選択式問題を作る。出力は
`english/schema/generation-result.schema.json` に準拠した JSON 1ファイル。

学習者は日本語では既にその内容を理解している前提。したがって問われるのは
「内容が分かるか」ではなく **「英語でその内容を読めるか」**。

## passage の書き方

- 80–200語。学術英語の文体（受動態・名詞化・関係詞を自然に含む）。
- **資料の内容を正確に写す。** 英語にするついでに主張を足したり丸めたりしない。
- 資料に出てくる記号・変数名（`n`, `O(log n)`, `T(n)`）はそのまま使う。

## question / choices / answer_index

- `choices` は 3–5 個。誤答選択肢は「読み違えたら選んでしまう」ものにする
  （語彙の取り違え、修飾関係の誤読、量化の誤読）。ランダムなダミーを混ぜない。
- `answer_index` は 0 始まり。
- `explanation` には **なぜ他の選択肢が違うか** まで書く。誤答時にそのまま提示される。

## sub_skill の選び分け

| 値 | どういう問題か |
|---|---|
| `comprehension` | 内容そのものを問う |
| `syntax_parsing` | 「この関係詞は何を修飾するか」「この it は何を指すか」 |
| `vocabulary` | passage 中の語の意味を文脈から問う |
| `reading_speed` | 平易だが量がある。時間で差がつく問題 |

`syntax_parsing` を混ぜるのは重要で、誤答原因の分類がここで初めて
「語彙不足」と「構文が取れていない」を区別できるようになる。

## reason

なぜこの設問を作ったか。誤答が続いたとき、資料の説明不足か本人の理解不足かを
判断する材料になるので、**資料のどの記述に対応する設問か**を書く。

## 制約

- passage に日本語を混ぜない。
- 資料に書かれていないことを正解にしない（一般常識で解ける問題にしない）。
- 1回の生成は依頼 JSON の `count_per_kind` 件まで。
