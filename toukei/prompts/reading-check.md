# 統計検定準1級「理解確認問題」生成プロンプト

`toukei_cli.py reading-next`で配信したその日の章（`chNN.pdf`）に対して、**過去問レベルより易しい**
理解確認問題を作る。目的は「読んだ章の内容が頭に入っているか」の確認であり、公式CBTと同じ難易度の
応用問題ではない。過去問レベルの問題（`--kind exam_level`、ストック）は別枠でこの後に出題される。

## 作る問題数

1章あたり5〜8問（章の分量に応じて調整してよい）。

## 難易度の基準（exam_levelとの違い）

- **やってよい**: 章で定義された用語・公式をそのまま問う。単純な代入計算。「この分布の期待値の公式は？」
  「この検定はどの前提条件が必要か？」など、章を読めば直接答えられる範囲。
- **やってはいけない**: 複数の概念を組み合わせる応用問題、章に載っていない一般化、
  過去問特有のひねった選択肢構成（`toukei/prompts/`に既存のexam_level生成基準があればそちらの水準）。
- 選択肢は4択。誤答選択肢は「よくある勘違い」レベルに留め、過度にトリッキーにしない
  （理解確認なので、消去法で潰せる程度でよい）。

## 出力形式

`items.json`として以下の配列を書く（`toukei_cli.py ingest`にそのまま渡せる形）:

```json
{
  "items": [
    {
      "question": "問題文（数式は$...$または独立行\\[...\\]で。裸のUnicode添字表記は使わない）",
      "choices": ["選択肢1", "選択肢2", "選択肢3", "選択肢4"],
      "answer_index": 0,
      "explanation": "なぜ正解か。章のどの定義・公式に基づくかを明記する（100〜200字程度でよい。exam_levelほど厚い解説は不要）"
    }
  ]
}
```

## 取り込みコマンド

```
python3 scripts/toukei_cli.py ingest --file items.json \
  --competency <competency_id> --set-id <YYYYMMDD> \
  --kind reading_check --chapter <章番号>
```

`--kind reading_check`を付けないと既定のexam_level（ストック）として扱われ、優先出題されなくなる点に注意。
